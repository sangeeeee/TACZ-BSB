# 实现说明

当前版本：NeoForge `1.0.0-beta`。仅维护当前数据格式，不提供跨版本兼容或数据迁移。

## 弹药与配方

注册 `tacz_bsb:improved_ammo` 与 `tacz_bsb:precise_ammo`，共享继承 TaCZ AmmoItem 的 TieredAmmoItem；`AmmoId` 表示口径，物品 ID 表示改良/精密等级。沿用原有弹药匹配接口、名称解析、堆叠限制与渲染器，不为每个口径注册独立 Item。因此新增枪包弹药不需要改变注册表，也无需重新构建本模组。

RecipeManager 在解析配方 JSON 前对所选命名空间进行成品替换。保留原 recipe ID，以替换后的唯一配方进入 Create 的正常配方管理和同步流程。只处理 `create:sequenced_assembly` 的顶层 `results` 中原为 `tacz:ammo` 的条目，保留其余 JSON；工作台、过渡物品与其他加工配方不会受到影响。

配方控制使用 COMMON 配置，因为 NeoForge 的 SERVER 配置在服务器首轮资源加载后才读取。直接伤害、爆炸伤害、装填顺序和 HUD 偏移仍使用同步的 SERVER 配置。

新增配方以标准 JSON 保存于 `data/tacz_bsb/recipe`。`tools/generate_precise_recipes.py` 从锁定的 Create: TaCZ JAR 生成材料注册表、父模型和配方，只是开发工具，运行模组不执行它。85 个新材料中 38 个为可堆叠原料/部件，47 个为不可堆叠的加工中物品。只有加工中物品继承 Create 的 SequencedAssemblyItem，避免其单个堆叠限制破坏批量配方。

所有新增序列严格保持原 Create: TaCZ 的工序顺序，生成脚本不前移火药。通过 Create 官方 `DeployerRecipeSearchEvent` 提供优先级 75 的后备分支，低于正常序列配方（100），高于普通机械手配方（50）。只处理生成表中的 23 对装药配方，按当前加载的配方逐步比较已完成操作：忽略过渡物品身份，核对机械类型、投入材料和设置。仅当已完成部分相同且另一分支接受当前材料时，才用同等进度的临时输入查询 Create 后续配方，实际物品不被提前修改或额外消耗。首次投入不同材料后无法切换，也不允许混用普通、高能火药。没有新增 Create Mixin。

所有过渡物品继续使用独立注册 ID 和 Create 的 `sequenced_assembly` 组件记录进度。47 个新增加工中物品和 29 个原 Create: TaCZ 加工中物品通过 `c:hidden_from_recipe_viewers` 标签从 JEI 搜索隐藏，创造栏事件也排除加工中物品。正常原料、已装药弹壳和成品继续显示。

## 弹匣与弹膛

`RoundQueue` 按击发顺序保存连续段：整数低两位为类型（1 普通、2 改良、3 精密），高位为数量。0 仅用于表示弹膛或击发结果为空。100 发同类弹只需一个段；混装才增加段数。`AmmoLedger` 区分 magazine、chamber、reserve、transfer：后两者分别记录已从物品栏取出而尚未装入的弹药，以及拉栓/退弹时刚从弹匣移出的弹药。

每次操作基于实际取弹结果执行。标准脚本回调结束时，将未使用的暂存弹药按品质返还，不允许凭请求数量填充生存弹匣。转入弹膛只移动记录；击发只消耗一发，霰弹一次发射多个投射物也只扣一发。取消事件不提交击发消费。

记录放在枪械 ItemStack 的独立 `tacz_bsb:ammo_state` 数据组件里，与 TaCZ 的原生弹量、弹膛布尔值一起更新。数据组件具备存档和网络编码。物品转移、丢弃和玩家重连继承物品状态；HUD读取同步后的状态，不决定服务端结果。

开膛供弹武器（如 RPG）按 TaCZ 的规则只从弹匣读取当前弹药，忽略无意义的弹膛标记。本模组的数据组件不允许为开膛供弹武器记录额外弹膛；不一致的数据直接拒绝，不修复历史格式。HUD 和免耗弹射击共用当前弹药选择规则，退弹不会返还这枚不存在的弹药。

除了 Lua API，还覆盖 LivingEntityShoot 在调用射击脚本之前自动上膛的独立路径。只接 Lua API 会漏掉这条原生路径。

TaCZ 新生成且没有本模组组件的枪械按原生数量初始化为普通弹。如果外部代码直接修改了已记账枪械的数量/弹膛，或者在装弹时更换口径，当前实现会明确拒绝不一致状态，而不是猜测并增删某种弹药。这种非标准改写需要额外适配。

## 伤害与外观

在 TaCZ 创建本次投射物时，捕获该次实际消耗的品质，然后将原生 `setShotDamageMultiplier` 的入参乘以本次弹药等级的倍率。爆炸伤害只通过字段访问器在初始化时乘以独立倍率。不修改投射物 tick，不新建投射物子类，不通过世界实体 ID 查找子弹，不替换命中算法。

TaCZ 原有距离曲线、配件增益和脚本单次射击倍率继续参与计算。爆炸半径、击退、穿透和爆头规则均由原有逻辑执行。

两档弹药物品模型以 `tacz:item/ammo` 为父模型，继承原版手持缩放和 GUI 正面光照。渲染使用有作用域的标记为两档强化弹药的 AmmoItemRenderer 增加原版附魔渲染缓冲：二维图标使用物品 glint，三维 Bedrock 模型使用实体 glint。嵌套渲染后恢复标记。右下角 HUD 通过 NeoForge 图层事件追加文字；不覆盖 TaCZ 原有 HUD 方法。

弹药盒使用独立 `box_tier` 整数组件标记等级（1/2/3）。为避免箱内类型信息丢失，一个盒子只接受同口径同品质的弹药。构造 TaCZ 的 AmmoBoxTooltip 时，将其中用于展示的普通弹药物品替换为盒内等级对应的物品；原 ClientAmmoBoxTooltip 用它统一生成名称、宽度与图标，复用已有等级颜色和附魔渲染。数量和创造盒无限符号继续由 TaCZ 显示，不再追加“内含……”文字。

## 兼容边界

已验证的是锁定版本的 TaCZ/Create: TaCZ 和标准枪械接口。支持通过 AmmoId、配置和标准配方数据扩展；不能保证任意附属模组无需适配。

以下情况需专项检查：绕开标准 API 修改枪械 NBT；跨多个异步回调先扣物品再延后装填；自行生成特殊投射物或伤害；其他模组覆写同一装填方法；改变正在装弹的枪械口径或供弹模式。燃料、创造和无限装填维持特殊供弹语义，不等同于普通生存子弹物品的逐发兑换。

状态编码和操作存在少量开销，大小与连续弹药段数有关；没有针对世界全部投射物的查找或每 tick 增伤。没有进行高并发压力测试，不能把简单测试解释为所有整合包下的零开销或绝对无冲突。


## 全类型创造弹药盒

`UniversalAmmoBoxItem` 继承 TaCZ 的 `AmmoBoxItem`，固定提供全类型创造盒语义。改良和精密分别注册为两个独立物品；品质由物品类型决定，`AmmoTransactions.boxTier` 在取弹时读取该品质，再走已有的装填与弹膛记账路径。无需按枪械编写映射，也不增加射击或实体 Mixin。

模型直接继承 `tacz:item/ammo_box/all_type_creative_ammo_box`，注册 TaCZ 原染色处理器，沿用原版无限供弹、附魔光效及全类型用途提示。两个物品加入 TaCZ 的 `OTHER_TAB`。
